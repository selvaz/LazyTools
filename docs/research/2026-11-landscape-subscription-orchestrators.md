## What nobody in the verified table does

No row combines all of the bridge's differentiators: **(1)** read *both* Claude and Codex subscription remaining allowances through supported interfaces and automatically choose the engine, **(2)** require a successful reviewer from the *other vendor* before completion, **(3)** detach durable worktree jobs while turning risky shell actions into resumable approval tickets, and **(4)** dispatch to either vendor's official cloud **without prior repository registration**. Native clouds necessarily authorize/connect a repository; local tools accept any checkout but are not zero-registration vendor clouds. Ruflo/routers optimize model/cost rules, and usage tools such as [ccusage](https://github.com/ryoppippi/ccusage) **V** calculate local token/cost logs; neither proves remaining subscription entitlement across both vendors. Thus “nobody” means “none found/verified,” not a universal negative.

## What to copy or reuse

* Reuse the **worktree + PTY/process adapter** pattern from Claude Squad, Vibe Kanban, or Emdash; Emdash's durable lifecycle, artifact-copy ordering, SSH hosts, and ticket intake are the strongest reference. Agent Orchestrator's CI/review-comment feedback loop is also directly reusable.
* Copy Conductor's clean separation of *workspace* from *harness*, Vibe Kanban's attempt/follow-up history and diff/merge UX, and Claude Squad's explicit apply/conflict recovery. Keep adapters invoking unmodified official CLIs; never scrape or export credentials.
* Model approval as a persisted state machine (requested/approved/denied/expired) and resume the same job. The surveyed tools mostly inherit an interactive prompt or disable it; this is a real gap.
* Implement cross-vendor review as a provider constraint plus recorded reviewer identity, not merely “run another agent.” Fall back visibly when the other vendor has no capacity; never silently self-review.
* For clouds, use documented vendor surfaces and accept registration: Codex Cloud/Claude web/GitHub/Jules are useful destinations, but “arbitrary local repo to vendor cloud with no authorization” is neither evidenced nor a safe promise.

## Policy risk (do not infer permission from technical possibility)

**Anthropic:** its [legal/compliance page](https://code.claude.com/docs/en/legal-and-compliance) **V** says each end user must authenticate themselves, subscription OAuth is for “ordinary use of Claude Code and other native Anthropic applications,” and third-party products/services should use API-key authentication. The [Consumer Terms](https://www.anthropic.com/legal/consumer-terms) **V** prohibit automated/non-human access except via API key or where explicitly permitted. Therefore launching the unmodified CLI for an owner may be lower risk than reusing OAuth, but unattended `claude -p` subscription orchestration is **not clearly blessed**; obtain written guidance and offer API mode. Never read credential files or call private usage endpoints.

**OpenAI:** official Codex supports ChatGPT-plan sign-in ([help](https://help.openai.com/en/articles/11369540-using-codex-with-your-chatgpt-plan) **V**) and the CLI deliberately exposes `codex exec`; however the [consumer Terms](https://openai.com/policies/row-terms-of-use/) **V** prohibit automatic/programmatic extraction of data/output and rate-limit circumvention. Newer documented [“use your ChatGPT plan in other apps”](https://help.openai.com/en/articles/20001542-using-your-chatgpt-plan-in-other-apps-and-sites) **V** is the safe authorization path for participating apps; do not assume a locally cached OAuth token grants that permission. Use the official executable/auth flow, user-scoped jobs, no credential forwarding, no quota circumvention, and seek confirmation for commercial unattended wrapping.
